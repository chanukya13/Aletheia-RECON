## Phase 6 — Interpretation trace

Build `/trace` as a read-only source search and interpretation workspace. Reuse Zod contracts, the core package, Fastify, TanStack Query, the existing source reader and dialog. Add a span-role manifest with a version, a pinned corpus hash, source-work grouping, explicit term mappings and roles for original-language edition, translation, editorial note, modern interpretation and modern tested material. Role mappings are assistant-curated drafts. They describe the edition at hand, including the printed Old English excerpt, and carry no manuscript-authentication claim.

Add a pure `traceInterpretations(corpus, manifest, query, excludedSpanIds)` function. Literal search uses exact original offsets, case-insensitive matching and Unicode-safe boundaries. Term variants resolve only through the explicit manifest. Candidate evidence follows candidate → assertion → input assertion → source span, including alternative supporting paths, with cycle protection. A contribution is excluded by span ID. Preserve surviving paths and distinguish omitted text by its rights. Restrict output to display-permitted source revisions before searching. Cap query length and excluded-span count. Return source revision hashes, roles, grouping, support paths, active/excluded status and a deterministic input/result fingerprint. Reject a stale role manifest and unknown exclusion IDs.

Expose `GET /api/v1/interpretation-trace` with bounded query parameters and a shared response schema. The UI provides a search form, literal result count, a list of candidate interpretations, source-role cards, exclusion/restoration controls, exact source dialogs and links into the existing eyesalve scenario editor. Show loading, empty and API-error states. Scope results to the pinned local corpus.

Implementation sequence is contracts and manifest, pure core projection, read-only API, UI/navigation, tests, production build and browser verification. Unit tests must catch unsupported spelling expansion, footnote exclusion, surviving alternate evidence, cycles, Unicode offsets, empty results, source rights and stale hashes. Integration tests check API bounds and database preservation. Browser tests at desktop and phone must search cropleac, inspect its original wording, remove and restore the editorial note, verify onion/leek support survives, inspect oxymel without invented quantities, check keyboard/dialog focus, overflow, Axe and unexpected console/network errors.

Phase 6 is complete only after its unit/API tests, typecheck/lint and actual production-browser journeys pass. Write `docs/handoffs/phase-6.md` with executed results and screenshots, then start Phase 7.

## Phase 7 — Matched measured outcomes

Build `/outcomes` with links from the trace and evidence workflows. Use the existing pinned `PMC6261618.xml`, XML parser and material versions. Add a server-side table adapter that verifies original raw SHA-256 and extracts Tables 1 and 2 by stable IDs. Parse the reported column labels, strain rows, units, statistic and replicate description. Build 16 uniquely identified numeric observations with original cell text, table/row/column location, source revision, material link and assay context. Parse the composition table to retain preparation differences. Reject malformed/duplicate headers, duplicate observation keys, missing values and changed hashes. Never fetch a replacement silently.

Define shared observation and contrast contracts and a pure core calculator. A comparison requires the same study, organism/strain, assay protocol, endpoint, statistic and units, positive exact uncensored values and distinct arms. Otherwise return explicit reasons and no ratio. Return onion divided by leek as a descriptive ratio of reported medians. Preserve source material differences, draft status and experimental scope. Provide actual source-cell inspection and JSON download sufficient to reproduce the arithmetic offline.

Expose read-only observation and contrast APIs with strict schema validation. The UI selects the strain, displays both modern reconstructions, their original values and units, ratio direction, material differences and exact source cells. Include a selectable real biofilm endpoint from the existing corpus to verify incompatibility handling. Unknown or nonnumeric observations remain unavailable with a reason. Handle failed loading and no eligible pair explicitly.

Implementation sequence is table extraction and frozen expected-cell fixture, pure contrast calculator, read-only routes, UI, then verification. Unit tests compare all 16 cells with independently specified expected values, shuffle columns, exercise missing/duplicate/censored values, strain/endpoint/unit mismatches and zero denominators. Integration tests verify source hash checks, linked materials, JSON arithmetic and no database mutations. Browser tests at desktop and phone must switch ATCC 6538 to LAC and obtain ratios 1 and 2, inspect exact cells, reject MIC/biofilm pairing, download/replay JSON, and check keyboard, overflow, Axe and console/network errors.

Phase 7 is complete only when its unit/API tests and browser gates pass and previous product regressions remain green. Record current data hashes and actual results in `docs/handoffs/phase-7.md`. Update the main plan and README to the executed status. Independent scientific review stays pending under the user's existing decision. No benchmark superiority is inferred from cell extraction fidelity or descriptive ratios.
